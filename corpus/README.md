# Корпус runbook'ов (RAG-источник)

Операционные runbook'и — пошаговые инструкции на типовые инциденты, по которым
отвечает ассистент. Это база знаний сервиса, а не его код.

## Важно: данные синтетические

Все runbook'и и любые идентификаторы в них (user_id, txn_id, суммы, IP, e-mail,
телефоны, номера карт) **выдуманы**. Реальных персональных или платёжных данных
здесь нет и быть не должно — корпус специально написан под публичную выкладку.
Номера карт не приводятся даже в маскированном виде, только последние четыре
цифры в формате `****1111`.

## Структура

- `runbooks/` — атомарные runbook'и, по одному инциденту в файле
  (`rb-NN-slug.md`). Каждый — по единому шаблону: Симптом → Область и влияние →
  Диагностика → Решение → Эскалация (L1→L2→L3) → Связано.
- Языки: 13 runbook'ов на русском, 3 (RB-06, RB-13, RB-16) — на английском.
  Смесь намеренная: эмбеддер bge-m3 многоязычный, и RAG-поиск проверяется на
  обоих языках — русский вопрос должен находить английский runbook.

Темы:

- **Платёжные сценарии** (вебхуки, идемпотентность, СБП-пополнение,
  автоконвертация, двойное списание, выпуск карт, сверка реестров).
- **Инфраструктура сервиса** (vLLM, latency/KV-cache, FastAPI-фасад, Prometheus,
  Loki/Promtail, PostgreSQL, диск/CrashLoop, CI).

## Как индексируется

RAG-слой (bge-m3 + reranker, индекс на CPU) читает `runbooks/`, режет файлы на
чанки и строит векторный индекс. Этот `README.md` в индекс не входит.
